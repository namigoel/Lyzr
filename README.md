# Coverage Desk

A git-native equity-research workbench built on [GitAgent / OpenGAP](https://github.com/open-gitagent/gitagent). A research agent drafts stock coverage; a human analyst reviews, edits, approves, rejects, or rolls it back — and every one of those actions is a real git commit, branch, merge, or revert on a live gitagent repository, not a database row.

Built for the Lyzr Founder's Office build assignment. See [WRITEUP.md](WRITEUP.md) for what this is, who it's for, the decisions behind it, and what's left broken on purpose. See [DEMO_SCRIPT.md](DEMO_SCRIPT.md) for a ~90-second recorded-walkthrough script.

## Setup

**Requires:** Node.js 18 or later (`node -v` to check), npm. No API keys, no accounts, no external services to configure.

```bash
git clone <this-repo-url>
cd coverage-desk
npm install        # installs express, simple-git, gray-matter, and the real @open-gitagent/opengap CLI
npm run seed       # builds agent-workspace/ from agent-template/ with ~6 weeks of realistic seed history
npm start          # starts the server at http://localhost:4173
```

Then open **http://localhost:4173** in a browser.

- `npm run seed` is destructive to `agent-workspace/` only (it deletes and rebuilds it from `agent-template/`) — run it any time to reset the demo back to its seeded state. `agent-workspace/` is gitignored; it's generated runtime state, not source, and `npm run seed` regenerates it deterministically every time.
- The research agent is deterministic by default — no LLM API key required to run or review this (see [WRITEUP.md](WRITEUP.md) for why). The one live external call is a read-only, unauthenticated market-data fetch to Yahoo Finance's public chart endpoint; if you're offline, the agent still runs but marks quotes `unavailable` rather than failing.

**Troubleshooting**
- *Port 4173 already in use:* `PORT=5050 npm start`, then open `http://localhost:5050`.
- *"workspace not initialized" error in the UI:* you skipped `npm run seed` — run it, then reload.
- *Node version too old:* this uses `fs.cpSync` and global `fetch`, both needing Node ≥ 18. Check with `node -v`.

## What to click

- Select **NVDA** — a name with a full incident: initiated, upgraded twice, over-conviction'd, reverted, and the mandate tightened in direct response. Check the **History** tab for the timeline and the **Diff** tab to compare any two revisions.
- Select **PYPL** — has a live pending agent draft sitting on a review branch, waiting for a human decision. Approve, edit-then-approve, or reject it.
- Select **RIVN** — not yet covered. Click **"Ask agent to initiate"** to run the real research → draft → mandate-check loop against live market data.
- Select **GMBL** — below the desk's mandate floor. The agent declines instead of drafting.
- Open **Mandate** in the top nav — `RULES.md` is versioned exactly like coverage. Edit it, propose the change on a branch, see the diff, merge it.
- The right-hand **Harness** panel runs the actual `opengap` CLI (`validate --compliance`, `info`, `audit`) against the live workspace — not a mock.

## How it's structured

```
agent-template/     the portable gitagent agent definition (source of truth, tracked in git)
  agent.yaml SOUL.md RULES.md DUTIES.md AGENTS.md
  skills/ tools/ knowledge/ memory/ workflows/ hooks/ compliance/ examples/

agent-workspace/     agent-template/ + git history — the live thing the workbench operates on
                     (gitignored — generated by `npm run seed`, see below)

server/              Express API: git operations, the deterministic agent loop, the opengap CLI wrapper
public/              the workbench UI (plain HTML/CSS/JS, no build step)
seed/seed.js          builds agent-workspace/ and backdates a realistic commit history into it
```

`agent-workspace/` is gitignored deliberately. It is a *running instance* of the agent (its own git repository, with its own commits, branches, and history), not source code — shipping a git repo nested inside another git repo is fragile, and it's more honest to ship the generator than a frozen snapshot. `npm run seed` is fully reproducible: same script, same narrative, every time. See WRITEUP.md for the tradeoff this creates.

## Why this is git-native, not a wrapper with git nearby

- **Memory is commits.** A ticker's recommendation *is* `memory/coverage/<TICKER>.md`. There is no separate database — the file's git history is the full audit trail of every rating, target, and rationale change, who made it, and when.
- **Branching is the review queue.** The agent never writes to `main`. It drafts on `review/<ticker>-<timestamp>`; the branch itself *is* the pending-review state, diffable against `main` at any time.
- **Diff is the review interface.** Approving a revision means reading a real `git diff`, not a re-rendered form.
- **Rollback is `git revert`, not an UPDATE statement.** The NVDA over-conviction call is reverted with two `git revert` commits, sitting right there in the log next to the mistake, both preserved.
- **The mandate is versioned too.** `RULES.md` is edited on a branch, diffed, and merged exactly like a coverage file — including a real amendment in the seed history, written in direct response to the NVDA incident.

## Real GitAgent integration

This isn't just gitagent-shaped files — `agent-workspace/` validates against the real, published `@open-gitagent/opengap` CLI:

```bash
npx @open-gitagent/opengap validate --compliance --dir ./agent-workspace
npx @open-gitagent/opengap info --dir ./agent-workspace
npx @open-gitagent/opengap audit --dir ./agent-workspace
```

The workbench's Harness panel runs these same commands live.
